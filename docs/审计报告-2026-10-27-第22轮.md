## 2. 决策审计：为什么"内网自用"仍然选择微软签名

有人可能会问：内网自用为什么还要花钱？这个决定必须能自洽，否则就是浪费预算。

| 方案 | 省下的 | 付出的 |
|---|---|---|
| 企业 CA + 关 Secure Boot | ¥3000~6000/年 | ①每台机进 BIOS 关 Secure Boot；②关闭启动链完整性验证（bootkit/rootkit 防护失效）；③**将来对外必须重走微软签名** |
| **微软签名** | — | ¥3000~6000/年 |

**关键判断依据是用户那句"后续就不好说了"**：既然将来可能对外，现在按对外标准做，将来零改动。
反过来，如果现在选企业 CA 路线，将来对外时不仅要重新采购 EV，还要把已经装出去的机器全部重装一次驱动。

所以这不是"多花钱"，而是**避免一次返工**。

**同时确认没有夸大**：
- 企业 CA + 关 Secure Boot 在技术上是**可行的**（微软例外条款明确写了 `Secure Boot is off in the BIOS` 可以加载受信任 CA 签的驱动），不是编造的方案；
- 只是代价与"将来对外"这个预期冲突，所以不选。文档里保留了这个选项与其代价，没有单方面抹掉。

## 3. 文档审计：README 曾严重失真（本轮修正）

这是本轮**实际的审计发现**，虽然是文档问题，但性质不轻：

| # | 失真内容 | 影响 |
|---|---|---|
| 1 | 完全没提 minifilter 驱动与 `driver/` 目录 | 任何人读 README 都会以为这是纯用户态产品 |
| 2 | 技术路线仍是旧口径，看不出 ProjFS **已被判定不可行** | 后来者可能基于错误前提继续投入 ProjFS |
| 3 | 文档索引缺 minifilter 设计、审计报告、签名采购流程 | 关键决策与风险文档找不到入口 |

**性质判断**：这不是"文档写得不够好"，而是**对外宣称了一个已经不存在的产品形态**。
新人接手、客户安全评审、三个月后的自己复盘，都会先读 README——读错就是方向错。

**已全部修正**，README 从 40 行扩到 95 行，新增「当前技术路线」表与里程碑状态表，
并明确标注 **M0~M2c 全部未经运行时验证**（不敢让读者误以为已经能用）。
