## 2. 项目定位与关键事实

- Pek.ROutGuard＝企业内部**文件防泄漏（DLP）**双端产品，Cargo workspace：
  - `core/`（`pek-outguard-core`）：容器格式 `OGD1`、规则引擎、协议模型、密钥派生——**双端共享**。
  - `server/`（`pek-outguard-server`）：管理端（面板 + 客户端 API + 数据库 + 密钥托管），默认端口 **5600**。
  - `client/`（`pek-outguard-client`）：终端（Windows 服务 + 文件监控 + 加密执行 + 受控打开 + 防退出）。
- 文档：`docs/需求说明书.md`（待确认口径在第 9 章）、`docs/架构设计.md`（含容器字节布局与密钥体系）。
- **加密容器是唯一对外格式**：明文头（公司信息/提示语/密级）+ AES-256-GCM 分块密文 + 尾部 KeyBlock + SHA-256 记录。
- **规则只由服务端下发**，客户端只执行；规则集与终端组多对多（多人共用规则）。
- **安全边界**：用户态方案不对抗本地管理员 + 内核工具/重装系统；不做进程注入/反杀软/键盘记录。

## 3. 构建 / 测试 / 打包

- 工具链：edition 2024；Windows 为主目标。
- 依赖（path，相对 `../`）：`dhrust=../DH.RustBase`、`pek-rcode=../Pek.RCode`、`pek-radmin=../Pek.RAdmin`、`pek-rwaf=../Pek.RWaf`——**编译报缺 API 时先拉新这几库再复测**。
- 日常：`cargo check`；调测：`cargo build --profile fast`；发版：`cargo build --release`。
- 回归：`cargo test`（每轮收尾必跑，贴实际输出）。

## 4. 提交与推送

- 提交说明用中文；`git commit -F <UTF-8 文件>`（不要用 `-m` 传中文，PS 5.1 会变 gb2312）。
- GitHub 推送遇 hosts 劫持用 IP 直连：`git -c http.curloptResolve=github.com:443:<IP> push origin main`。
- 每轮收尾三件套：① 决策记录新增节（含用户原话）② `tools/continuity/sync-memory.ps1` 回灌 `docs/项目记忆.md` ③ 回归验证如实汇报。
