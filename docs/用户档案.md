# 用户档案（工作偏好与方式）

> 本文件随每个项目仓库携带，供任何电脑上的 AI 快速"了解用户"。维护：发现新偏好时补充。
> 请用户审阅增改（2026-10 起沉淀）。

## 1. 沟通方式
- 中文交流；指令简洁，偏好"直接推进 + 关键处确认"。
- 重大口径（数字 / 定位 / 对外表述）先确认再落文；重大改动要能看到证据（截图 / 验证输出）。
- 三条主线关切：**不遗漏**（换电脑 / 换会话可接续）、**口径一致**（全项目统一）、**有记录**（决策可追溯、含原话）。

## 2. 通用工作偏好
- 排查问题优先在本地电脑找源码 / 文件，不用反编译 DLL。
- 密钥类信息**不做成可配置项**（有意硬编码于源码常量，文档不展开明文）；凭据类信息不明文落盘（用可逆加密，如 enc:v1/AES-GCM）。
- 不使用他人项目的签名文件；文档重"口径与依据"。
- 多项目并行；主语言 C#，兼 Go / Rust / Zig / Python / Node.js；深度使用 AI 辅助开发。
- 常用平台：Windows + PowerShell 5.1（含中文的 .ps1 必须 UTF-8 with BOM；跑 python 前设 `$env:PYTHONIOENCODING='utf-8'`）。
- git 远程习惯用 codeup.aliyun.com（私有库）；NuGet 走公司内网镜像。

## 3. 工程习惯
- 一切产物"可重建"：文档 / PPT 由脚本生成，改内容改脚本；不手工改二进制产物。
- 跨电脑开发是常态：脚本路径必须便携（按脚本位置推导）；AI 记忆以**仓库内 md** 为准（本机记忆不跨设备）。
- 验证文化：改完跑回归（脚本 / 测试 / 截图），并记录验证结果。
- 表述红线（文档类项目通用）：数字口径 / 术语 / 量词全篇统一；范围数字用连字符（-）。
